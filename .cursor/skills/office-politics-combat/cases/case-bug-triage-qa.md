# Case: 任务分发的"中央集权 vs 直分"博弈

本案例展示 **「输入 → 局势判断 → 三档输出 → 钩子 → 反击」** 的完整闭环。重点是 agent 如何在面对**白手套 + 上级双簧**时构造三档方案。

> 本案例为**复合示例**：方法论结构来自跨部门协作的常见模式，对话样本由作者改写虚构，
> 不对应任何具体公司、人物或事件。文中所有角色名（Me / Boss / QA_Gatekeeper 等）均为通用代称，
> 可替换为读者自己环境中的对应角色。如读者在阅读时联想到具体某人或某事件，纯属议题本身的普遍性，
> 不构成对任何真实主体的指涉。

---

## 0. 适用场景（不止 IT 行业）

这个案例的"形状"是：**一项工作可以直接分发给执行人，但被某中间角色坚持要"先过我这里再分"，并以"流程""单点风险""人力不足"为由拒绝直分。**

它在以下场景里都成立：

| 行业 | 具体形态 |
|------|---------|
| 互联网 | 工单 / 任务 / 需求要先经过某 leader 再转手 |
| 制造 / 品控 | 异常单要先报到品质组长再下派 |
| 律所 / 咨询 | 任务必须经过 partner 秘书 / PMO 再分发到具体律师 |
| 政府 / 国企 | 文件流转必须先经办公室再到具体处室 |
| 学术 / 行政 | 申请要先到院办再到具体老师 |

读案例时把"工单 / 任务"换成你所在行业的等价物即可，方法论不变。

---

## 1. 输入（用户提供，已脱敏）

```text
【我是谁】Me，某业务条线一线执行者
【对方是谁】
  - Boss：直属上级，有 PUA 倾向，习惯用 QA_Gatekeeper 做白手套
  - QA_Gatekeeper：相邻团队负责人，倾向于把分发权握在自己手里
【渠道】工作群 IM（半公开，部分围观者在场）
【议题概述】
  - 现状：任务先派给 QA_Gatekeeper，再由其转给具体执行人
  - 我的提议：直接派给具体执行人，跳过中间一手
  - QA_Gatekeeper 的反对话术（典型四类）：
    1. 流程化拖延（"得先有文档 / 工具支持"）
    2. 大词挡箭（"上面不是说要 XX 战略吗，正好等等那个"）
    3. 人力借口（"我们没有人力"）
    4. 大项目挡箭（"我们正在做几个重点项目"）
  - Boss 介入后用三段式：
    1. 成本模糊化（"对你方而言成本一样"）
    2. 中心点反用（"设具体 owner 反而引入单点风险"）
    3. 共情包装（"万一他休假了影响处理时效"）
【我的诉求】
  1. 不让 QA_Gatekeeper 把分发权变成扩权工具
  2. 让 Boss 之后无法继续用四板斧堵议题
  3. 让议题在群 / 文档里公开化，必要时升级
  4. 不撕破脸，保留长期合作空间
【红线】
  - 不直接跟 Boss / QA_Gatekeeper 翻脸
  - 不被贴"不配合""情绪化"标签
```

---

## 2. 局势判断

典型的**白手套组合拳**：QA_Gatekeeper 在前面用流程话术拖延扩权；Boss 在背后用"成本 / 单点 / 共情"三件套帮 QA_Gatekeeper 做合理化包装。议题表面是"任务怎么分"，实际是"分发权由谁掌握"。

---

## 3. 对方话术解构

对照 [pua-counters.md](../pua-counters.md)：

| 对方话术类型 | 真实意图 |
|------------|---------|
| 流程化拖延 | 把议题推到不确定时间，等议题自己消失 |
| 转述式挡箭（大词战略） | 用大词框架转移议题 |
| 人力借口 | 不可验证的挡箭牌 |
| 大项目挡箭 | 强化人力借口 |
| 成本模糊化（A1）| 抹平真实多维成本 |
| 系统背锅（C1）| 把人的责任推给"系统 / 工具" |
| 中心点反用（A2）| 把"有 owner"说成"风险" |
| 共情包装 | 让反对方案看起来像"关心同事" |

**组合识别：典型的复合诡辩。单点反驳任何一句都会被另几句反弹回来。**

---

## 4. 我方筹码与风险

**筹码：**

- 有现成的执行链路数据可以拉（任务时延、转手时长）
- "人力不足"是模糊声明，对方答不出具体数字
- 同级 / 下游可能也对现状有意见，可作为隐性盟友
- "单点 / 休假"风险本身可以反用到 QA_Gatekeeper 自己身上

**风险：**

- Boss 已亲自下场，正面硬怼成本太高
- QA_Gatekeeper 已积累"流程合规"人设，不好直接否
- 当前在半公开 IM，留痕不够正式

**风险评估打分（[framework.md](../framework.md) §4）：**

| 维度 | 评估 | 分值 |
|------|-----|-----|
| 离职成本 | 中 | 0 |
| Boss 报复能力 | 中高 | 0 |
| 事件可公开度 | 中（可推到文档 / 工单系统）| 0 |
| 我方数据 | 较充分 | +1 |
| 盟友数量 | 中 | 0 |
| 业务重要性 | 中 | 0 |

总分 +1，**默认走标准档**；考虑到 Boss 已亲自下场，**保留温和倾向**——避免开局即正面对抗。

## 5. 三档方案

### 5.1 温和档

**回复对象：只回 QA_Gatekeeper，不直接接 Boss 那段。**

> @QA_QA_Gatekeeper 收到，理解大家都忙。为了让我这边能给上下游一个说法，能拉齐几个数字吗：
>
> 1. 当前任务从派给你到转到执行人，平均经过几道手 / 几个工作日？
> 2. 如果做工具支持，大概几人日？由谁来排期？
> 3. 你提到的几个重点项目，分别是哪几位 owner？我同步上下游预期时好对齐。
>
> 我这边先把当前的执行链路数据整理一下，稍后同步到协作文档。

**埋下的钩子：**

- 成本量化钩子（[hook-patterns.md](../hook-patterns.md) §2）—— "几人日 / 哪位同学"
- 责任归位钩子（§3）—— "几位 owner"
- 时间戳钩子（§9，隐形版）—— "我这边先整理同步到文档"

**预期对方走向：** 拖延 / 不回（你公开化已生效）/ 给夸张数字（你拆分反问）/ Boss 再次介入（进入反击模式）/ 妥协（直接赢）。

---

### 5.2 标准档（推荐）

**回复对象：在工作群 @Boss 和 @QA_QA_Gatekeeper，把议题摊到台面上。**

> @Boss @QA_QA_Gatekeeper 基于刚才的讨论，整理一下现状和下一步建议：
>
> **现状：**
>
> 1. 任务目前先派给 QA_Gatekeeper 再转给执行人，端到端有几个工作日的额外时延（具体数据我同步整理）
> 2. 关于"自动分发准确性"的顾虑，准确率需要先对齐到具体数字
> 3. 关于"QA_Gatekeeper 是单点"的顾虑——标准做法应是 primary + backup，而不是"不设具体 owner"
>
> **建议：**
>
> 1. 一周内先把执行链路时延、分发准确率两个数据拉齐
> 2. 基于数据决定方案：是改进自动分发逻辑（owner：@分发逻辑负责人），还是改进现有转手 SOP（owner：@QA_QA_Gatekeeper）
> 3. 不论选哪条，都需要明确 primary + backup 的 SOP
>
> 如无异议，我本周先出数据 + 草案 doc，大家 review。

**埋下的钩子：**

- 书面化钩子（§1）—— "整理 doc，无异议我推进"
- 责任归位钩子（§3）—— 两条候选路径都标 owner
- 时间戳钩子（§9）—— "一周内"
- 优先级确认钩子（§7）—— "改自动分发还是改 SOP"

**预期对方走向：** Boss 不便公开反对（你没攻击他、还自己揽了活）；QA_Gatekeeper 想拖也得拖出新借口；Boss 若再用"四板斧"，议题已上文档，他无法重复模糊话术。

---

### 5.3 强硬档

**回复对象：协作文档 + 邮件，抄送平级团队 / 上下游。**

> 主题：[流程对齐] 任务分发 SOP & 数据 review
>
> Hi @Boss @QA_QA_Gatekeeper，抄送 @平级负责人，
>
> 关于任务分发流程，同步当前情况和建议，请协助决策：
>
> **背景：** 当前任务先经 QA_Gatekeeper 再转手到执行人，对端到端时延和上下游体感有影响。讨论中有三个顾虑：成本差异、自动分发准确性、QA_Gatekeeper 成为单点。
>
> **为支持决策，建议先对齐三组数据：**
>
> 1. 端到端时延（owner：我，<时间>前）
> 2. 自动分发准确率（owner：@分发逻辑负责人，<时间>前）
> 3. 多维成本拆分（时间 / 响应 / 累计）
>
> **两个待决策项：**
>
> 1. 是否按 primary + backup 设计 SOP
> 2. 自动分发改进的 owner 归属
>
> 建议 <时间> 前对齐，需拉会我可以约。
>
> Thanks

**埋下的钩子：**

- 公开化钩子（§5）—— 抄送平级负责人 + 文档化
- 责任归位钩子（§3）—— "分发逻辑负责人"摆出来
- 时间戳钩子（§9）
- 文档引用钩子（§10）—— "primary + backup 是行业通用做法"，对方反对就是反对通用做法

**代价：** Boss 会明确感受到你在"搞事情"。**仅在你已经做好换组 / 换工作预案时再用强硬档**。

---

## 6. 推荐档位

**推荐：标准档**。理由：

1. 你的红线是"不撕破脸、保留合作空间"，强硬档成本太高
2. 温和档无法回应 Boss 的"四板斧"，他会继续压
3. 标准档措辞中性、把议题推向数字化 + 书面化，对方无法反对"先拉数据"
4. 如果标准档被对方继续耍赖，**再升级到强硬档会更有理**（"我已经尝试过温和对齐"是很好的升级理由）

## 7. 下一步监测 & 升级路径

### 48 小时内监测信号

| 对方反应 | 解读 | 下一步 |
|---------|-----|-------|
| QA_Gatekeeper 给数据 | 议题进入理性轨道 | 按数据讨论方案 |
| QA_Gatekeeper 拖延 | 触发量化钩子 | 一两个工作日后 @ 一次 + 抄 Boss |
| Boss 帮 QA_Gatekeeper 用新话术 | 进入反击模式 | 见 §8 |
| Boss 私下找你说"别搞这么正式" | 触发公开化钩子 | 私聊后回 IM 总结："谢谢提醒，数据对齐方向我们按原计划推" |
| 无任何回应 | 沉默即默认 | 几个工作日后自行推进 doc，同步到群 |

### 升级路径

- 几个工作日内没有数据对齐 → 软升级：周报里写上这个阻塞点
- 议题超过两周无进展 → 议题升级：约 BigBoss 1on1 谈业务（不谈人）
- 出现明显打压 / 报复 → 关系升级准备：证据备份 + 换组 / 离职预案

### 关系修复动作（核心原则 §11）

若实际走了标准档以上路径，下一周做一次"主动让一次小利"：在不相关的议题上配合 QA_Gatekeeper 一次、或在群里夸她团队最近某项具体成果。**目的是降低秋后算账概率，不是和解**。

## 8. 模拟第二轮（反击模式演示）

假设 Boss 接着发一段类似话术（情绪施压 + 人设 PUA + 指责不配合），核心动作是反对书面化、模糊化责任、不给时间。

### 钩子回收表

| 钩子（统一引用 [hook-patterns.md](../hook-patterns.md) 章节号）| 是否触发 | 对方动作 | 强度 |
|------|---------|---------|-----|
| 公开化钩子（标准档 §1）| **强触发** | 反对书面化 | 强 |
| 责任归位钩子（§3）| **绕开** | 不说 owner | 中 |
| 时间戳钩子（§9）| **绕开** | 不给时间 | 中 |
| 优先级确认钩子（§7）| **绕开** | 不拍板 | 中 |

**整体动作识别：** Boss 用"小题大做 / 正式 / 配合"三连压你。

### 第二轮三档反击

**温和档：**

> @Boss 理解你希望轻量。我先跟 QA_Gatekeeper 对一下时延数据，基于数据再看要不要改流程。如果数据没问题，就按现状走。本周同步结果。

新埋钩子：时间戳 + "基于数据"隐形钩——把对方逼到数据面前。

**标准档（推荐）：**

> @Boss 我也希望轻量推进。同步一下我的思路：
>
> - 这件事确实小，但**没有数据 / 没有 SOP** 的情况下每次都重复讨论，长期 cost 反而更高
> - 所以我只想先做一件事：**拉一下当前转手时延的数据**。如果显示现状没问题，我们就维持，我也不再提；如果有问题，再讨论方案
> - 数据我本周内出，不需要 QA_Gatekeeper 配合任何开发动作
>
> 这样轻量吗？

新埋钩子：一致性挑战钩子（[tactics-defense.md](../tactics-defense.md) §7）+ 优先级确认钩子 + 互惠陷阱（§11）。

**强硬档：**

> @Boss 谢谢提醒。同步一下我的理解：
>
> - "不用正式" —— 我整理 doc 是为了减少后续反复讨论，不是把事情做大
> - "QA_Gatekeeper 已经在做了" —— 我没看到具体动作同步。能请 @QA_QA_Gatekeeper 同步当前进展和 deadline 吗？我也好对齐给上下游
> - "你们配合一下" —— 我们一直在配合。建议把"配合"的具体定义也对齐一下，避免理解偏差
>
> 这些要求都不过分，能帮忙回应下吗？

新埋钩子：衡量标准钩子（[hook-patterns.md](../hook-patterns.md) §6）+ 责任归位钩子（[hook-patterns.md](../hook-patterns.md) §3，二次使用）+ 一致性挑战钩子（[tactics-defense.md](../tactics-defense.md) §7）。

**第二轮推荐：标准档**——用"我让步"消解"不配合"指控；把议题继续钉在"拉数据"这个对方无法拒绝的点上；对方再反对"拉数据"，就是明显理亏。

## 9. 从这个案例要记住什么

1. **复合诡辩不要一条条反驳**——换框（从"方案细节"换到"责任归属 + 数据"）
2. **钩子比表态重要**：每一轮都要埋新钩子
3. **让步要让在无关紧要的点上**（数据我自己出），大头不退
4. **渠道决定胜负**：私聊 → 群 → 文档 → 邮件，逐步推高书面化层级
5. **不要硬怼上级本人**，只怼议题、只回具体事实
6. **PUA 词汇（"小题大做""配合""不用正式"）要识别后再回**，不要接它们的词
7. **赢完要做关系修复**：下周主动让一次小利，把秋后算账概率压到最低
