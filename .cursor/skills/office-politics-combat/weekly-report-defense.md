# Weekly Report Defense：周报防御写法

周报是低冲突、高留痕的防御工事。适合把风险、阻塞、决策需求写进正式节奏，避免对方事后说“不知道”。

---

## 1. 写法原则

- 写业务影响，不写人际矛盾。
- 写当前状态，不写情绪判断。
- 写需要的决策，不写抱怨。
- 每条都带 owner / deadline / link，缺什么就明确写缺什么。

---

## 2. 固定结构

```text
完成：
- <事项>：完成 <结果>，链接 <Jira / MR / Doc>

风险：
- <风险名>：当前影响 <影响范围>，已同步 <渠道 / 链接>，等待 <owner / deadline / 风险等级> 确认。

阻塞：
- <事项>：阻塞点为 <具体事实>，当前等待 <人 / 团队> 在 <日期> 前给结论。

需要决策：
- <议题>：建议 A / B 二选一；若选择 A，影响是 X；若选择 B，影响是 Y。
```

---

## 3. 常用句式

### 风险未定级

> <风险> 已建 Jira：<link>。当前仍待平台侧确认风险等级、owner 和预计修复时间。

### 对方未响应

> <事项> 已于 <日期> 在 <渠道> 同步，目前仍待 <团队 / owner> 回复。若 <日期> 前无结论，建议升级到 <会议 / owner> 对齐。

### 需要老板拍优先级

> 当前 A / B / C 存在资源冲突。如果 <新事项> 需要本周完成，需要确认 A / B / C 中哪个降优先级。

### 风险接受

> 若该风险本周期暂不处理，需要确认风险接受人和接受周期，避免后续责任不清。

---

## 4. 发布治理 / 审批链路类样例

```text
风险：
- 某发布审批链路存在身份可信度风险，已建工单：<link>。当前等待对方一侧确认 owner、修复时间、风险等级，以及是否需要历史审批记录排查。
```

升级版：

```text
需要决策：
- 该审批链路身份可信度风险目前尚未明确 owner / deadline。建议确认是否按发布治理 / 安全风险处理；如暂不处理，需要明确风险接受人和接受周期。
```

---

## 5. 避免写法

不要写：

```text
QA 一直不配合。
老板偏袒 QA。
这个以后出事不是我的锅。
```

改成：

```text
当前仍待平台侧确认 owner / deadline。
当前风险等级尚未明确，需要决策人确认处理优先级。
如暂不处理，需要明确风险接受人和接受周期。
```
