# ADR-0002 · 全程本地模型，不接云端 API

- 状态：Accepted
- 日期：2026-06-13

## 背景

`agent-lab` 是一个学习项目，会跑大量循环 (ReAct / Plan-Solve / Multi-Agent / Eval)。是否把云端 API (例如方舟 / OpenAI) 也作为可选 backend，需要明确取舍。

## 决策

**只接本地模型，不接任何云端 API**。所有 LLM 调用走本地 OpenAI 兼容 server。

## 理由

- **节奏与成本**：学 Agent 控制流时频繁触发循环，云端速率限制与计费会让节奏卡顿；本地推理"想跑就跑"。
- **可控性**：本地模型的能力与失败模式更稳定，便于把 Agent 的行为与"模型能力天花板"分开观察。
- **可重放**：本地起的 server 在固定权重 + 温度=0 下基本可重放，对 M9 评测稳定性友好。
- **隐私练习**：尽管本项目数据不敏感，但工程实践应默认"先本地、再上云"。

## 反方意见

- 缺少与云端强模型的对照：模型能力差异确实存在。 → 用 XL 档 (14B) 与 L 档 (7B) 的对照覆盖这一面，足够让评测有差异性。
- 本地推理跨平台部署成本高。 → 用 llama.cpp / Ollama 两套方案降低门槛，详见 ADR-0003。

## 影响

- LLM 客户端只实现一个 `openai-compatible` provider，不再做 vendor 适配。
- 配置项 `OPENAI_BASE_URL` / `OPENAI_API_KEY` 仍然保留（API_KEY 在本地后端通常是占位字符串）。
- 未来若要切到云端，**只需改一个 base URL**，agent 代码层零改动；这条路径有意保留。
