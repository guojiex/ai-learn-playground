# 05 · 业务场景：台湾电商文案

所有里程碑共用同一套领域，避免学到第 7 步还要重新建语料。

## 领域定位

- **市场**：台湾。
- **平台**：蝦皮 (Shopee TW)、momo 購物網、小红书台湾区。
- **角色**：中小型卖家 / 联盟营销 (affiliate) 撰稿人。
- **典型任务**：
  - SKU 卖点提炼 (从规格 → 用户语言)
  - 平台化标题生成 (字数限制、关键词、Emoji 风格)
  - 多平台文案改写 (蝦皮简短 vs. 小红书叙事)
  - 标签 / 关键词生成
  - 合规检查 (违禁词、夸大宣传、医疗化妆品声明)
  - 风格切换 (理性测评 vs. 闺蜜安利)

## 与 lora/ 的关系

`lora/` 训练数据 (`tw_affiliate.jsonl`) 给我们示范了"台味黑话密度"和"卖家角色口吻"。`agent-lab` **不直接消费** 那个 jsonl，而是基于它的语感另写小而精的样例数据。理由：

- 学 Agent 不是学微调，混着会模糊重点。
- Agent 的样例需要"结构化 SKU + 平台规则"，而 LoRA 的样例是"prompt → 文案"对，结构不同。

## 样例数据 (M0–M3 用)

在 `data/products/` 存 5–10 个手写 SKU JSON：

```json
{
  "id": "sku_001",
  "name": "日本製 純棉吸水浴巾 大尺寸 70x140",
  "brand": "今治本舗",
  "category": "家居 / 浴巾",
  "price_twd": 690,
  "specs": {
    "material": "100% 純棉",
    "size": "70 x 140 cm",
    "weight_g": 480,
    "origin": "日本"
  },
  "highlights": [
    "今治認證",
    "蓬鬆吸水",
    "不易掉毛",
    "可機洗"
  ],
  "stock": 32,
  "shipping": "現貨 / 24h 出貨"
}
```

字段不必齐全，故意留缺失项以便 Agent 通过工具/对话补全。

## 平台规则 (M5 用)

在 `data/platform_rules/` 各放一份 markdown：

- `shopee_tw.md`：标题 ≤ 60 字、Emoji 适度、"現貨 / 免運" 类关键词偏好、敏感词清单。
- `momo.md`：偏理性、强调规格与保固、慎用感叹号。
- `xhs_tw.md`：第一人称叙事、首段抓注意力、标签 5–10 个。

这些 markdown 在 M5 被切片、嵌入、检索；在 M2 也可以被工具直接 grep。

## 评测样例 (M9 用)

在 `data/eval/` 放：

- `prompts.jsonl`：10–20 条 "请为这个 SKU 在 X 平台写文案" 的输入。
- `judge_rubric.md`：LLM-as-Judge 的评分维度 (信息覆盖 / 平台合规 / 黑话密度 / 流畅度)。
- `expected.jsonl`：可选的"理想答案"参考，给人工对照用。

## 工具集合 (跨里程碑)

| 工具 | 出现里程碑 | 作用 |
|------|------------|------|
| `product_lookup` | M2 起 | 按 id / 关键词查 SKU |
| `price_format` | M2 起 | 价格 → "NT$690 (限時免運)" 这类展示串 |
| `platform_lint` | M2 起 | 按平台规则校验文案 (字数 / 敏感词 / 标签数) |
| `slang_check` | M2 起 | 黑话密度计算，复用 `lora/` 的清单 |
| `http_get` | M5+ | 拉取额外页面 (本机 mock 服务即可) |
| `calc` | 任意 | 折扣 / 单价计算 |
| `sqlite_query` | M4+ | 读写记忆库 / approval |

## 合规与口径

- 不真实访问外部站点，所有"在线数据"都用本地 mock 服务模拟，避免反爬与不稳定。
- 不输出任何医疗 / 投资 / 极限词宣传。`platform_lint` 内置一份基础敏感词表，用作工具调用的真实业务约束。
- 涉及"卖家偏好"的长期记忆，在 M4 用伪造的 `seller_id` 演示，不接真实卖家数据。
